Przewodnik konfiguracji

Przewodnik konfiguracji komputera. Do włączania potrzebne są ustawienia z części 1. Zdalne wyłączanie przez SSH (część 2) jest opcjonalne.

1. Wake-on-LAN (ustawienia komputera)

Magiczny pakiet wybudza wyłączony lub uśpiony komputer, ale tylko jeśli jego karta sieciowa wciąż jest zasilana i nasłuchuje. Użyj kabla sieciowego: przez Wi-Fi budzenie rzadko działa.

Linux

W BIOS/UEFI włącz Wake on LAN (nazwy bywają różne: Wake on LAN, Power On By PCI-E, Resume by PCI-E). Jeśli jest opcja ErP, EuP lub głębokiego uśpienia, wyłącz ją, ponieważ odcina zasilanie karty sieciowej.

Znajdź nazwę interfejsu sieciowego (na przykład enp8s0):

ip -br link

Sprawdź ustawienie Wake-on. Musi pokazywać g:

sudo ethtool <iface> | grep Wake-on

Włącz je (resetuje się po ponownym uruchomieniu):

sudo ethtool -s <iface> wol g

Aby zachować je po restartach przy użyciu NetworkManager (zamień nazwę połączenia, zobacz nmcli connection show):

sudo nmcli connection modify "<connection>" 802-3-ethernet.wake-on-lan magic

Windows

W BIOS/UEFI włącz Wake on LAN (nazwy bywają różne: Wake on LAN, Power On By PCI-E, Resume by PCI-E). Jeśli jest opcja ErP, EuP lub głębokiego uśpienia, wyłącz ją, ponieważ odcina zasilanie karty sieciowej.

Otwórz Menedżera urządzeń, kliknij dwukrotnie kartę sieciową, karta Zarządzanie energią: zaznacz „Zezwalaj temu urządzeniu na wybudzanie komputera” i „Zezwalaj na wybudzanie komputera tylko magicznemu pakietowi”.

W tym samym oknie, karta Zaawansowane: ustaw „Wake on Magic Packet” na Enabled (jeśli jest na liście).

Wyłącz szybkie uruchamianie: Panel sterowania → Opcje zasilania → Wybierz działanie przycisków zasilania → Zmień ustawienia, które są obecnie niedostępne → odznacz „Włącz szybkie uruchamianie”. Przy włączonym szybkim uruchamianiu wyłączony komputer często ignoruje magiczny pakiet.

macOS

Otwórz Ustawienia systemowe → Bateria (MacBook) lub Energia (Mac stacjonarny) → Opcje i włącz „Wybudzaj na potrzeby dostępu do sieci”. Budzenie działa najlepiej przez Ethernet: w MacBooku użyj adaptera Ethernet USB-C lub Thunderbolt i trzymaj go podłączonego do zasilania. Uśpiony Mac połączony przez Wi-Fi często ignoruje magiczny pakiet.

Przy Wi-Fi wyłącz też „Prywatny adres Wi-Fi” dla swojej sieci (Ustawienia systemowe → Wi-Fi → Szczegóły), w przeciwnym razie Mac dostanie inny adres MAC. Na liście poniżej „Ethernet Address” to adres MAC każdego portu.

W WakeDeck dodaj urządzenie z adresem MAC komputera. Znajdziesz go tutaj:

Linux

ip -br link

Windows

ipconfig /all

macOS

networksetup -listallhardwareports

Adres rozgłoszeniowy: ostatni adres Twojej sieci, na przykład 192.168.1.255 dla 192.168.1.x (domyślny 255.255.255.255 też działa w tej samej sieci). Port: 9.

2. Zdalne wyłączanie przez SSH (opcjonalnie)

Zastąp PASTE_KEY_LINE_FROM_APP wierszem klucza widocznym na ekranie Klucz SSH w WakeDeck.

Aplikacja loguje się własnym kluczem, nigdy hasłem. Komputer potrzebuje serwera SSH i musi mieć dodany klucz publiczny aplikacji. Poniższe polecenia już zawierają Twój klucz.

Linux

Zainstaluj i uruchom serwer SSH (przykład dla Debiana/Ubuntu):

sudo apt install openssh-server && sudo systemctl enable --now ssh

W Fedorze, Archu i SteamOS usługa nazywa się sshd:

sudo systemctl enable --now sshd

Dodaj klucz aplikacji do swojego użytkownika. Ten wiersz ogranicza klucz do polecenia wyłączania:

mkdir -p ~/.ssh && chmod 700 ~/.ssh && echo 'PASTE_KEY_LINE_FROM_APP' >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys

Zezwól na wyłączanie bez hasła. Uruchom to, a potem dodaj wiersz poniżej (zamień youruser i sprawdź ścieżkę poleceniem: which shutdown):

sudo visudo -f /etc/sudoers.d/wakedeck
youruser ALL=(ALL) NOPASSWD: /usr/bin/shutdown

Windows

W PowerShell jako administrator zainstaluj i uruchom OpenSSH Server:

Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0; Start-Service sshd; Set-Service -Name sshd -StartupType Automatic

Konto administratora: dodaj klucz i zablokuj uprawnienia pliku (w przeciwnym razie SSH go zignoruje):

Add-Content -Force -Path "$env:ProgramData\ssh\administrators_authorized_keys" -Value 'PASTE_KEY_LINE_FROM_APP'
icacls.exe "$env:ProgramData\ssh\administrators_authorized_keys" /inheritance:r /grant "Administrators:F" /grant "SYSTEM:F"

W zwykłym koncie umieść wiersz klucza w C:\Users\NAZWA\.ssh\authorized_keys.

Jeśli nadal odmawia: sprawdź, czy zapora zezwala na port TCP 22 (funkcja OpenSSH zwykle dodaje regułę) oraz czy konto nie jest kontem Microsoft Entra ID, które nie może używać kluczy.

macOS

Włącz serwer SSH: Ustawienia systemowe → Ogólne → Udostępnianie → Zdalne logowanie i zezwól swojemu użytkownikowi.

Dodaj klucz aplikacji do swojego użytkownika. Ten wiersz ogranicza klucz do polecenia wyłączania:

mkdir -p ~/.ssh && chmod 700 ~/.ssh && echo 'PASTE_KEY_LINE_FROM_APP' >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys

Zezwól na wyłączanie bez hasła. Uruchom to, a potem dodaj wiersz poniżej (zamień youruser):

sudo visudo -f /etc/sudoers.d/wakedeck
youruser ALL=(ALL) NOPASSWD: /sbin/shutdown

Na ekranie edycji urządzenia wpisz hosta (IP lub nazwę), użytkownika SSH (nazwę swojego konta na komputerze) i port (22). Dotknij Wyłącz teraz. Za pierwszym razem sprawdź, czy wyświetlony odcisk zgadza się z odciskiem komputera, a potem dotknij Zaufaj. Odcisk komputera:

Linux

ssh-keygen -lf /etc/ssh/ssh_host_ecdsa_key.pub

Windows

ssh-keygen -lf $env:ProgramData\ssh\ssh_host_ecdsa_key.pub

macOS

ssh-keygen -lf /etc/ssh/ssh_host_ecdsa_key.pub

„Komputer odrzucił klucz SSH”: zły klucz lub nazwa użytkownika. „Nie udało się połączyć”: komputer jest wyłączony albo host, port lub zapora są nieprawidłowe. „Komputer odpowiedział błędem”: w Linuksie lub macOS zwykle chodzi o regułę sudoers. „Klucz SSH komputera się zmienił”: komputer zainstalowano od nowa lub jego klucze SSH wygenerowano ponownie; zaufaj nowemu kluczowi tylko wtedy, gdy się tego spodziewasz.

3. Poza domem (VPN)

Spoza sieci domowej najpierw potrzebujesz sposobu, by się do niej dostać, na przykład VPN WireGuard lub Tailscale. Magiczny pakiet to rozgłoszenie, a wiele sieci VPN go nie przekazuje. Wpisz w urządzeniu adres rozgłoszeniowy swojej sieci (na przykład 192.168.1.255). Jeśli zdalne włączanie nadal nie działa, zwykłym rozwiązaniem jest małe, zawsze włączone urządzenie w domu, które wyśle pakiet za Ciebie (router z Wake-on-LAN lub Raspberry Pi). Zdalne wyłączanie przez SSH działa przez VPN, o ile adres komputera jest osiągalny.

Problemy zdalne: „brak połączenia z siecią lub VPN” oznacza, że telefon nie ma trasy do tego adresu, więc najpierw połącz VPN. „Nie znaleziono adresu rozgłoszeniowego” oznacza, że nazwy lub adresu w urządzeniu nie da się rozpoznać. VPN może też przyjąć pakiet i nigdy go nie dostarczyć: aplikacja nie może tego stwierdzić, bo magiczny pakiet nie ma odpowiedzi. Sprawdź, czy komputer się włącza, i spójrz na jego stan na liście.
