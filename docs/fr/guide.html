Guide de configuration

Guide de configuration du PC. L’allumage nécessite les réglages de la section 1. L’extinction à distance par SSH (section 2) est facultative.

1. Wake-on-LAN (réglages du PC)

Un paquet magique allume un PC éteint ou en veille, mais seulement si sa carte réseau est encore alimentée et à l’écoute. Utilisez un câble réseau : le Wi-Fi fonctionne rarement pour l’allumage à distance.

Linux

Dans le BIOS/UEFI, activez Wake on LAN (les noms varient : Wake on LAN, Power On By PCI-E, Resume by PCI-E). S’il existe une option ErP, EuP ou deep sleep, désactivez-la, car elle coupe l’alimentation de la carte réseau.

Trouvez le nom de l’interface réseau (par exemple enp8s0) :

ip -br link

Vérifiez le réglage Wake-on. Il doit afficher g :

sudo ethtool <iface> | grep Wake-on

Activez-le (cela se réinitialise au redémarrage) :

sudo ethtool -s <iface> wol g

Pour le conserver après les redémarrages avec NetworkManager (remplacez le nom de la connexion, voir nmcli connection show) :

sudo nmcli connection modify "<connection>" 802-3-ethernet.wake-on-lan magic

Windows

Dans le BIOS/UEFI, activez Wake on LAN (les noms varient : Wake on LAN, Power On By PCI-E, Resume by PCI-E). S’il existe une option ErP, EuP ou deep sleep, désactivez-la, car elle coupe l’alimentation de la carte réseau.

Ouvrez le Gestionnaire de périphériques, double-cliquez sur votre carte réseau, onglet Gestion de l’alimentation : cochez « Autoriser ce périphérique à sortir l’ordinateur du mode veille » et « Autoriser uniquement un paquet magique à sortir l’ordinateur du mode veille ».

Dans la même fenêtre, onglet Avancé : réglez « Wake on Magic Packet » sur Activé (s’il est présent).

Désactivez le démarrage rapide : Panneau de configuration → Options d’alimentation → Choisir l’action des boutons d’alimentation → Modifier des paramètres actuellement non disponibles → décochez « Activer le démarrage rapide ». Lorsque le démarrage rapide est activé, un PC éteint ignore souvent le paquet magique.

macOS

Ouvrez Réglages Système → Batterie (MacBook) ou Énergie (Mac de bureau) → Options, et activez « Réactiver pour l’accès au réseau ». Le réveil fonctionne mieux en Ethernet : sur un MacBook, utilisez un adaptateur Ethernet USB-C ou Thunderbolt et laissez-le branché sur le secteur. Un Mac en veille sur Wi-Fi ignore souvent le paquet magique.

En Wi-Fi, désactivez aussi « Adresse Wi-Fi privée » pour votre réseau (Réglages Système → Wi-Fi → Détails), sinon le Mac reçoit une autre adresse MAC. Dans la liste ci-dessous, « Ethernet Address » est l’adresse MAC de chaque port.

Dans WakeDeck, ajoutez l’appareil avec l’adresse MAC du PC. Pour la trouver :

Linux

ip -br link

Windows

ipconfig /all

macOS

networksetup -listallhardwareports

Adresse de diffusion : la dernière adresse de votre réseau, par exemple 192.168.1.255 pour 192.168.1.x (la valeur par défaut 255.255.255.255 fonctionne aussi sur le même réseau). Port : 9.

2. Extinction à distance par SSH (facultatif)

Remplacez PASTE_KEY_LINE_FROM_APP par la ligne de clé affichée dans l’écran Clé SSH de WakeDeck.

L’app se connecte avec sa propre clé, jamais avec un mot de passe. Le PC doit disposer d’un serveur SSH et la clé publique de l’app doit y être ajoutée. Les commandes ci-dessous contiennent déjà votre clé.

Linux

Installez et démarrez le serveur SSH (exemple pour Debian/Ubuntu) :

sudo apt install openssh-server && sudo systemctl enable --now ssh

Sous Fedora, Arch ou SteamOS, le service s’appelle plutôt sshd :

sudo systemctl enable --now sshd

Ajoutez la clé de l’app à votre utilisateur. La ligne limite la clé à la commande d’extinction :

mkdir -p ~/.ssh && chmod 700 ~/.ssh && echo 'PASTE_KEY_LINE_FROM_APP' >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys

Autorisez l’extinction sans mot de passe. Exécutez ceci, puis ajoutez la ligne en dessous (remplacez youruser et vérifiez le chemin avec : which shutdown) :

sudo visudo -f /etc/sudoers.d/wakedeck
youruser ALL=(ALL) NOPASSWD: /usr/bin/shutdown

Windows

Dans PowerShell en tant qu’administrateur, installez et démarrez le serveur OpenSSH :

Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0; Start-Service sshd; Set-Service -Name sshd -StartupType Automatic

Compte administrateur : ajoutez la clé et verrouillez les autorisations du fichier (sinon SSH l’ignore) :

Add-Content -Force -Path "$env:ProgramData\ssh\administrators_authorized_keys" -Value 'PASTE_KEY_LINE_FROM_APP'
icacls.exe "$env:ProgramData\ssh\administrators_authorized_keys" /inheritance:r /grant "Administrators:F" /grant "SYSTEM:F"

Pour un compte normal : placez la ligne de la clé dans C:\Users\NAME\.ssh\authorized_keys.

Si l’accès est toujours refusé : vérifiez que le pare-feu autorise le port TCP 22 (la fonctionnalité OpenSSH ajoute normalement la règle) et que le compte n’est pas un compte Microsoft Entra ID, qui ne peut pas utiliser de clés.

macOS

Activez le serveur SSH : Réglages Système → Général → Partage → Session à distance, et autorisez votre utilisateur.

Ajoutez la clé de l’app à votre utilisateur. La ligne limite la clé à la commande d’extinction :

mkdir -p ~/.ssh && chmod 700 ~/.ssh && echo 'PASTE_KEY_LINE_FROM_APP' >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys

Autorisez l’extinction sans mot de passe. Exécutez ceci, puis ajoutez la ligne en dessous (remplacez youruser) :

sudo visudo -f /etc/sudoers.d/wakedeck
youruser ALL=(ALL) NOPASSWD: /sbin/shutdown

Dans l’écran de modification de l’appareil, renseignez l’hôte (IP ou nom), l’utilisateur SSH (le nom de votre compte sur le PC) et le port (22). Touchez Éteindre maintenant. La première fois, vérifiez que l’empreinte affichée correspond à celle du PC, puis touchez Faire confiance. L’empreinte du PC :

Linux

ssh-keygen -lf /etc/ssh/ssh_host_ecdsa_key.pub

Windows

ssh-keygen -lf $env:ProgramData\ssh\ssh_host_ecdsa_key.pub

macOS

ssh-keygen -lf /etc/ssh/ssh_host_ecdsa_key.pub

« Le PC a refusé la clé SSH » : clé ou nom d’utilisateur incorrect. « Connexion impossible » : le PC est éteint, ou l’hôte, le port ou le pare-feu est incorrect. « Le PC a répondu par une erreur » : sous Linux ou macOS, c’est généralement la règle sudoers. « La clé SSH du PC a changé » : le PC a été réinstallé ou ses clés SSH ont été régénérées ; n’acceptez la nouvelle clé que si vous vous y attendiez.

3. Hors de chez vous (VPN)

Depuis l’extérieur de votre réseau domestique, il vous faut d’abord un moyen d’y accéder, par exemple un VPN WireGuard ou Tailscale. Un paquet magique est une diffusion, et de nombreux VPN ne transmettent pas les diffusions. Indiquez l’adresse de diffusion de votre réseau (par exemple 192.168.1.255) dans l’appareil. Si l’allumage à distance ne fonctionne toujours pas, la solution habituelle est un petit appareil toujours allumé chez vous qui envoie le paquet à votre place (un routeur avec Wake-on-LAN, ou un Raspberry Pi). L’extinction à distance par SSH fonctionne via un VPN tant que l’adresse du PC est joignable.

Problèmes à distance : « pas de connexion réseau ou VPN » signifie que le téléphone n’a pas de route vers cette adresse ; connectez d’abord le VPN. « Adresse de diffusion introuvable » signifie que le nom ou l’adresse saisi dans l’appareil ne peut pas être résolu. Un VPN peut aussi accepter le paquet sans jamais le transmettre : l’app ne peut pas le savoir, car un paquet magique n’a pas de réponse. Vérifiez que le PC s’allume et consultez son état dans la liste.
