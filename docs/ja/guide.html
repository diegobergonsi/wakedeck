セットアップガイド

PC のセットアップガイドです。起動にはセクション 1 の設定が必要です。SSH によるリモートシャットダウン（セクション 2）は任意です。

1. Wake-on-LAN（PC の設定）

マジックパケットは、電源が切れている、またはスリープ中の PC を起動できます。ただし、ネットワークカードに電力が供給され、待ち受けている場合に限ります。LAN ケーブルを使用してください。Wi-Fi では起動できないことがほとんどです。

Linux

BIOS/UEFI で Wake on LAN を有効にします（名称は機種により異なります：Wake on LAN、Power On By PCI-E、Resume by PCI-E）。ErP、EuP、ディープスリープのオプションがある場合は、ネットワークカードへの電力が遮断されるため無効にしてください。

ネットワークインターフェース名を調べます（例：enp8s0）：

ip -br link

Wake-on の設定を確認します。g と表示される必要があります：

sudo ethtool <iface> | grep Wake-on

有効にします（再起動するとリセットされます）：

sudo ethtool -s <iface> wol g

NetworkManager で再起動後も維持するには（接続名を置き換えてください。nmcli connection show を参照）：

sudo nmcli connection modify "<connection>" 802-3-ethernet.wake-on-lan magic

Windows

BIOS/UEFI で Wake on LAN を有効にします（名称は機種により異なります：Wake on LAN、Power On By PCI-E、Resume by PCI-E）。ErP、EuP、ディープスリープのオプションがある場合は、ネットワークカードへの電力が遮断されるため無効にしてください。

デバイス マネージャーを開き、ネットワーク アダプターをダブルクリックして、[電源の管理] タブで「このデバイスで、コンピューターのスタンバイ状態を解除できるようにする」と「マジック パケットでのみ、コンピューターのスタンバイ状態を解除できるようにする」にチェックを入れます。

同じウィンドウの [詳細設定] タブで、「Wake on Magic Packet」を有効にします（一覧にある場合）。

高速スタートアップを無効にします：コントロール パネル → 電源オプション → 電源ボタンの動作を選択する → 現在利用可能ではない設定を変更します →「高速スタートアップを有効にする」のチェックを外します。高速スタートアップが有効だと、シャットダウンした PC がマジックパケットを無視することがよくあります。

macOS

システム設定 → バッテリー（MacBook）またはエネルギー（デスクトップ Mac）→ オプションで、「ネットワークアクセスによるスリープ解除」をオンにします。起動はイーサネット接続が最適です。MacBook では USB-C または Thunderbolt のイーサネットアダプタを使い、電源につないでおいてください。Wi-Fi 接続でスリープ中の Mac は、マジックパケットを無視することがよくあります。

Wi-Fi を使う場合は、お使いのネットワークの「プライベート Wi-Fi アドレス」もオフにしてください（システム設定 → Wi-Fi → 詳細）。オフにしないと Mac の MAC アドレスが変わります。下の一覧の「Ethernet Address」が各ポートの MAC アドレスです。

WakeDeck で、PC の MAC アドレスを使ってデバイスを追加します。確認方法：

Linux

ip -br link

Windows

ipconfig /all

macOS

networksetup -listallhardwareports

ブロードキャストアドレス：ネットワークの最後のアドレスです。たとえば 192.168.1.x のネットワークなら 192.168.1.255 です（同じネットワーク内では既定値の 255.255.255.255 も使えます）。ポート：9。

2. SSH によるリモートシャットダウン（任意）

PASTE_KEY_LINE_FROM_APP は、WakeDeck の SSH 鍵画面に表示される鍵の行に置き換えてください。

アプリは専用の鍵でログインし、パスワードは使いません。PC には SSH サーバーが必要で、アプリの公開鍵を追加しておく必要があります。以下のコマンドには、すでにあなたの鍵が含まれています。

Linux

SSH サーバーをインストールして起動します（Debian/Ubuntu の例）：

sudo apt install openssh-server && sudo systemctl enable --now ssh

Fedora、Arch、SteamOS ではサービス名が sshd です：

sudo systemctl enable --now sshd

アプリの鍵をユーザーに追加します。この行により、鍵はシャットダウンコマンドだけに制限されます：

mkdir -p ~/.ssh && chmod 700 ~/.ssh && echo 'PASTE_KEY_LINE_FROM_APP' >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys

パスワードなしでシャットダウンできるようにします。次を実行し、その下の行を追加してください（youruser を置き換え、which shutdown でパスを確認してください）：

sudo visudo -f /etc/sudoers.d/wakedeck
youruser ALL=(ALL) NOPASSWD: /usr/bin/shutdown

Windows

管理者として PowerShell を開き、OpenSSH サーバーをインストールして起動します：

Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0; Start-Service sshd; Set-Service -Name sshd -StartupType Automatic

管理者アカウント：鍵を追加し、ファイルのアクセス許可を制限します（そうしないと SSH はファイルを無視します）：

Add-Content -Force -Path "$env:ProgramData\ssh\administrators_authorized_keys" -Value 'PASTE_KEY_LINE_FROM_APP'
icacls.exe "$env:ProgramData\ssh\administrators_authorized_keys" /inheritance:r /grant "Administrators:F" /grant "SYSTEM:F"

通常のアカウントの場合：鍵の行を C:\Users\NAME\.ssh\authorized_keys に置きます。

それでも拒否される場合：ファイアウォールが TCP ポート 22 を許可していること（OpenSSH 機能は通常ルールを自動で追加します）と、アカウントが鍵を使えない Microsoft Entra ID アカウントではないことを確認してください。

macOS

SSH サーバーをオンにします：システム設定 → 一般 → 共有 → リモートログイン。そしてお使いのユーザーを許可します。

アプリの鍵をユーザーに追加します。この行により、鍵はシャットダウンコマンドだけに制限されます：

mkdir -p ~/.ssh && chmod 700 ~/.ssh && echo 'PASTE_KEY_LINE_FROM_APP' >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys

パスワードなしでシャットダウンできるようにします。次を実行し、その下の行を追加してください（youruser を置き換えます）：

sudo visudo -f /etc/sudoers.d/wakedeck
youruser ALL=(ALL) NOPASSWD: /sbin/shutdown

デバイスの編集画面で、ホスト（IP または名前）、SSH ユーザー（PC のアカウント名）、ポート（22）を入力します。「今すぐシャットダウン」をタップします。初回は、表示されたフィンガープリントが PC のものと一致することを確認してから「信頼する」をタップしてください。PC のフィンガープリント：

Linux

ssh-keygen -lf /etc/ssh/ssh_host_ecdsa_key.pub

Windows

ssh-keygen -lf $env:ProgramData\ssh\ssh_host_ecdsa_key.pub

macOS

ssh-keygen -lf /etc/ssh/ssh_host_ecdsa_key.pub

「PC が SSH 鍵を拒否しました」：鍵またはユーザー名が違います。「接続できませんでした」：PC の電源が切れているか、ホスト、ポート、ファイアウォールが正しくありません。「PC がエラーを返しました」：Linux や macOS では通常 sudoers のルールが原因です。「PC の SSH 鍵が変更されました」：PC が再インストールされたか、SSH 鍵が再生成されました。想定どおりの場合にのみ新しい鍵を信頼してください。

3. 外出先から（VPN）

自宅ネットワークの外からは、まずネットワークに入る手段が必要です（例：WireGuard や Tailscale の VPN）。マジックパケットはブロードキャストであり、多くの VPN はブロードキャストを転送しません。デバイスには、ネットワークのブロードキャストアドレス（例：192.168.1.255）を設定してください。それでも遠隔で起動できない場合は、代わりにパケットを送ってくれる常時稼働の小さな機器を自宅に置くのが一般的な解決策です（Wake-on-LAN 対応のルーターや Raspberry Pi など）。SSH によるリモートシャットダウンは、PC のアドレスに到達できれば VPN 経由でも動作します。

遠隔でのトラブル：「ネットワークまたは VPN に接続されていません」は、スマートフォンにそのアドレスへの経路がないという意味です。先に VPN に接続してください。「ブロードキャストアドレスが見つかりません」は、デバイスの名前またはアドレスを解決できないという意味です。VPN がパケットを受け取っても届けない場合もあります。マジックパケットには応答がないため、アプリには判断できません。PC が起動するかを確認し、一覧で状態を見てください。
