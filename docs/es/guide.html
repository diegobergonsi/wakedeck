Guía de configuración

Guía de configuración del PC. Para encender hacen falta los ajustes de la sección 1. El apagado remoto por SSH (sección 2) es opcional.

1. Wake-on-LAN (ajustes del PC)

Un paquete mágico enciende un PC apagado o suspendido, pero solo si su tarjeta de red sigue recibiendo energía y escuchando. Usa un cable de red: por Wi-Fi rara vez funciona el encendido.

Linux

En la BIOS/UEFI, activa Wake on LAN (los nombres varían: Wake on LAN, Power On By PCI-E, Resume by PCI-E). Si hay una opción ErP, EuP o deep sleep, desactívala, porque corta la energía a la tarjeta de red.

Busca el nombre de la interfaz de red (por ejemplo enp8s0):

ip -br link

Comprueba el ajuste Wake-on. Debe mostrar g:

sudo ethtool <iface> | grep Wake-on

Actívalo (se restablece al reiniciar):

sudo ethtool -s <iface> wol g

Para conservarlo tras los reinicios con NetworkManager (sustituye el nombre de la conexión, consulta nmcli connection show):

sudo nmcli connection modify "<connection>" 802-3-ethernet.wake-on-lan magic

Windows

En la BIOS/UEFI, activa Wake on LAN (los nombres varían: Wake on LAN, Power On By PCI-E, Resume by PCI-E). Si hay una opción ErP, EuP o deep sleep, desactívala, porque corta la energía a la tarjeta de red.

Abre el Administrador de dispositivos, haz doble clic en tu adaptador de red y ve a la pestaña Administración de energía: marca «Permitir que este dispositivo reactive el equipo» y «Permitir solo que un paquete mágico reactive el equipo».

En la misma ventana, pestaña Opciones avanzadas: pon «Wake on Magic Packet» en Habilitado (si aparece).

Desactiva el inicio rápido: Panel de control → Opciones de energía → Elegir el comportamiento de los botones de inicio/apagado → Cambiar la configuración actualmente no disponible → desmarca «Activar inicio rápido». Con el inicio rápido activado, un PC apagado suele ignorar el paquete mágico.

macOS

Abre Ajustes del Sistema → Batería (MacBook) o Energía (Mac de sobremesa) → Opciones y activa “Activar para acceso a la red”. El encendido funciona mejor por cable: en un MacBook usa un adaptador Ethernet USB-C o Thunderbolt y déjalo enchufado a la corriente. Un Mac suspendido por Wi-Fi suele ignorar el paquete mágico.

Si usas Wi-Fi, desactiva también “Dirección Wi-Fi privada” para tu red (Ajustes del Sistema → Wi-Fi → Detalles), o el Mac tendrá otra dirección MAC. En la lista de abajo, “Ethernet Address” es la dirección MAC de cada puerto.

En WakeDeck, añade el dispositivo con la dirección MAC del PC. Dónde encontrarla:

Linux

ip -br link

Windows

ipconfig /all

macOS

networksetup -listallhardwareports

Dirección de difusión: la última dirección de tu red, por ejemplo 192.168.1.255 para 192.168.1.x (el valor predeterminado 255.255.255.255 también funciona en la misma red). Puerto: 9.

2. Apagado remoto por SSH (opcional)

Sustituye PASTE_KEY_LINE_FROM_APP por la línea de clave que muestra la pantalla Clave SSH de WakeDeck.

La app inicia sesión con su propia clave, nunca con una contraseña. El PC necesita un servidor SSH y hay que añadirle la clave pública de la app. Los comandos de abajo ya incluyen tu clave.

Linux

Instala e inicia el servidor SSH (ejemplo para Debian/Ubuntu):

sudo apt install openssh-server && sudo systemctl enable --now ssh

En Fedora, Arch o SteamOS el servicio se llama sshd:

sudo systemctl enable --now sshd

Añade la clave de la app a tu usuario. La línea limita la clave al comando de apagado:

mkdir -p ~/.ssh && chmod 700 ~/.ssh && echo 'PASTE_KEY_LINE_FROM_APP' >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys

Permite apagar sin contraseña. Ejecuta esto y después añade la línea de debajo (sustituye youruser y comprueba la ruta con: which shutdown):

sudo visudo -f /etc/sudoers.d/wakedeck
youruser ALL=(ALL) NOPASSWD: /usr/bin/shutdown

Windows

En PowerShell como administrador, instala e inicia el servidor OpenSSH:

Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0; Start-Service sshd; Set-Service -Name sshd -StartupType Automatic

Cuenta de administrador: añade la clave y restringe los permisos del archivo (si no, SSH lo ignora):

Add-Content -Force -Path "$env:ProgramData\ssh\administrators_authorized_keys" -Value 'PASTE_KEY_LINE_FROM_APP'
icacls.exe "$env:ProgramData\ssh\administrators_authorized_keys" /inheritance:r /grant "Administrators:F" /grant "SYSTEM:F"

Para una cuenta normal: pon la línea de la clave en C:\Users\NAME\.ssh\authorized_keys.

Si sigue rechazando la conexión: comprueba que el cortafuegos permite el puerto TCP 22 (la característica OpenSSH normalmente añade la regla) y que la cuenta no es una cuenta de Microsoft Entra ID, que no puede usar claves.

macOS

Activa el servidor SSH: Ajustes del Sistema → General → Compartir → Sesión remota, y permite a tu usuario.

Añade la clave de la app a tu usuario. La línea limita la clave al comando de apagado:

mkdir -p ~/.ssh && chmod 700 ~/.ssh && echo 'PASTE_KEY_LINE_FROM_APP' >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys

Permite apagar sin contraseña. Ejecuta esto y después añade la línea de debajo (sustituye youruser):

sudo visudo -f /etc/sudoers.d/wakedeck
youruser ALL=(ALL) NOPASSWD: /sbin/shutdown

En la pantalla de edición del dispositivo, rellena el host (IP o nombre), el usuario SSH (el nombre de tu cuenta en el PC) y el puerto (22). Toca Apagar ahora. La primera vez, comprueba que la huella mostrada coincide con la del PC y toca Confiar. La huella del PC:

Linux

ssh-keygen -lf /etc/ssh/ssh_host_ecdsa_key.pub

Windows

ssh-keygen -lf $env:ProgramData\ssh\ssh_host_ecdsa_key.pub

macOS

ssh-keygen -lf /etc/ssh/ssh_host_ecdsa_key.pub

«El PC rechazó la clave SSH»: clave o nombre de usuario incorrectos. «No se pudo conectar»: el PC está apagado, o el host, el puerto o el cortafuegos son incorrectos. «El PC respondió con un error»: en Linux o macOS suele ser la regla de sudoers. «Ha cambiado la clave SSH del PC»: el PC se reinstaló o se regeneraron sus claves SSH; confía en la nueva clave solo si lo esperabas.

3. Fuera de casa (VPN)

Desde fuera de tu red doméstica primero necesitas una forma de entrar en ella, por ejemplo una VPN WireGuard o Tailscale. Un paquete mágico es una difusión, y muchas VPN no reenvían difusiones. Pon la dirección de difusión de tu red (por ejemplo 192.168.1.255) en el dispositivo. Si aun así el encendido remoto no funciona, la solución habitual es un pequeño dispositivo siempre encendido en casa que envíe el paquete por ti (un router con Wake-on-LAN o una Raspberry Pi). El apagado remoto por SSH funciona a través de una VPN mientras se pueda llegar a la dirección del PC.

Problemas en remoto: «sin conexión de red ni VPN» significa que el teléfono no tiene ruta hacia esa dirección, así que conecta primero la VPN. «No se encontró la dirección de difusión» significa que el nombre o la dirección del dispositivo no se puede resolver. Una VPN también puede aceptar el paquete sin entregarlo nunca: la app no puede saberlo, porque un paquete mágico no tiene respuesta. Comprueba que el PC se enciende y mira su estado en la lista.
