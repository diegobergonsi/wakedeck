Einrichtungsanleitung

Einrichtungsanleitung für den PC. Zum Aufwecken sind die Einstellungen aus Abschnitt 1 nötig. Das Herunterfahren per SSH (Abschnitt 2) ist optional.

1. Wake-on-LAN (PC-Einstellungen)

Ein Magic Packet weckt einen ausgeschalteten oder schlafenden PC auf, aber nur, wenn seine Netzwerkkarte noch mit Strom versorgt wird und lauscht. Verwende ein Netzwerkkabel: Über WLAN klappt das Aufwecken selten.

Linux

Aktiviere im BIOS/UEFI Wake on LAN (die Namen variieren: Wake on LAN, Power On By PCI-E, Resume by PCI-E). Gibt es eine Option ErP, EuP oder Deep Sleep, schalte sie aus, denn sie trennt die Netzwerkkarte vom Strom.

Finde den Namen der Netzwerkschnittstelle heraus (zum Beispiel enp8s0):

ip -br link

Prüfe die Einstellung Wake-on. Sie muss g anzeigen:

sudo ethtool <iface> | grep Wake-on

Aktiviere sie (wird beim Neustart zurückgesetzt):

sudo ethtool -s <iface> wol g

So bleibt sie mit NetworkManager nach Neustarts erhalten (ersetze den Verbindungsnamen, siehe nmcli connection show):

sudo nmcli connection modify "<connection>" 802-3-ethernet.wake-on-lan magic

Windows

Aktiviere im BIOS/UEFI Wake on LAN (die Namen variieren: Wake on LAN, Power On By PCI-E, Resume by PCI-E). Gibt es eine Option ErP, EuP oder Deep Sleep, schalte sie aus, denn sie trennt die Netzwerkkarte vom Strom.

Öffne den Geräte-Manager, doppelklicke auf deinen Netzwerkadapter und wähle die Registerkarte Energieverwaltung: Aktiviere „Gerät kann den Computer aus dem Ruhezustand aktivieren“ und „Nur Magic Packet kann den Computer aus dem Ruhezustand aktivieren“.

Im selben Fenster, Registerkarte Erweitert: Setze „Wake on Magic Packet“ auf Aktiviert (falls aufgeführt).

Deaktiviere den Schnellstart: Systemsteuerung → Energieoptionen → Auswählen, was beim Drücken von Netzschaltern geschehen soll → Einige Einstellungen sind momentan nicht verfügbar → Haken bei „Schnellstart aktivieren“ entfernen. Bei aktivem Schnellstart ignoriert ein heruntergefahrener PC das Magic Packet oft.

macOS

Öffne Systemeinstellungen → Batterie (MacBook) oder Energie (Desktop-Mac) → Optionen und aktiviere “Aufwecken für Netzwerkzugriff”. Das Aufwecken klappt am besten per Ethernet: Nutze am MacBook einen USB-C- oder Thunderbolt-Ethernet-Adapter und lass ihn am Strom. Ein schlafender Mac im WLAN ignoriert das Magic Packet oft.

Schalte im WLAN auch “Private WLAN-Adresse” für dein Netzwerk aus (Systemeinstellungen → WLAN → Details), sonst bekommt der Mac eine andere MAC-Adresse. In der Liste unten ist “Ethernet Address” die MAC-Adresse des jeweiligen Anschlusses.

Füge in WakeDeck das Gerät mit der MAC-Adresse des PCs hinzu. So findest du sie:

Linux

ip -br link

Windows

ipconfig /all

macOS

networksetup -listallhardwareports

Broadcast-Adresse: die letzte Adresse deines Netzwerks, zum Beispiel 192.168.1.255 für 192.168.1.x (der Standard 255.255.255.255 funktioniert im selben Netzwerk ebenfalls). Port: 9.

2. Herunterfahren per SSH (optional)

Ersetze PASTE_KEY_LINE_FROM_APP durch die Schlüsselzeile aus dem Bildschirm SSH-Schlüssel in WakeDeck.

Die App meldet sich mit ihrem eigenen Schlüssel an, nie mit einem Passwort. Der PC braucht einen SSH-Server, und der öffentliche Schlüssel der App muss dort hinzugefügt werden. Die Befehle unten enthalten bereits deinen Schlüssel.

Linux

SSH-Server installieren und starten (Beispiel für Debian/Ubuntu):

sudo apt install openssh-server && sudo systemctl enable --now ssh

Unter Fedora, Arch oder SteamOS heißt der Dienst stattdessen sshd:

sudo systemctl enable --now sshd

Füge den Schlüssel der App zu deinem Benutzer hinzu. Die Zeile beschränkt den Schlüssel auf den Herunterfahren-Befehl:

mkdir -p ~/.ssh && chmod 700 ~/.ssh && echo 'PASTE_KEY_LINE_FROM_APP' >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys

Erlaube das Herunterfahren ohne Passwort. Führe dies aus und füge dann die Zeile darunter hinzu (ersetze youruser und prüfe den Pfad mit: which shutdown):

sudo visudo -f /etc/sudoers.d/wakedeck
youruser ALL=(ALL) NOPASSWD: /usr/bin/shutdown

Windows

Installiere und starte den OpenSSH-Server in PowerShell als Administrator:

Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0; Start-Service sshd; Set-Service -Name sshd -StartupType Automatic

Administratorkonto: Füge den Schlüssel hinzu und schränke die Dateiberechtigungen ein (sonst ignoriert SSH die Datei):

Add-Content -Force -Path "$env:ProgramData\ssh\administrators_authorized_keys" -Value 'PASTE_KEY_LINE_FROM_APP'
icacls.exe "$env:ProgramData\ssh\administrators_authorized_keys" /inheritance:r /grant "Administrators:F" /grant "SYSTEM:F"

Bei einem normalen Konto: Lege die Schlüsselzeile in C:\Users\NAME\.ssh\authorized_keys ab.

Wird der Zugriff weiterhin abgelehnt: Prüfe, ob die Firewall den TCP-Port 22 erlaubt (das OpenSSH-Feature legt die Regel normalerweise an) und ob das Konto kein Microsoft-Entra-ID-Konto ist, denn diese können keine Schlüssel verwenden.

macOS

Schalte den SSH-Server ein: Systemeinstellungen → Allgemein → Teilen → Entfernte Anmeldung, und erlaube deinen Benutzer.

Füge den Schlüssel der App zu deinem Benutzer hinzu. Die Zeile beschränkt den Schlüssel auf den Herunterfahren-Befehl:

mkdir -p ~/.ssh && chmod 700 ~/.ssh && echo 'PASTE_KEY_LINE_FROM_APP' >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys

Erlaube das Herunterfahren ohne Passwort. Führe dies aus und füge dann die Zeile darunter hinzu (ersetze youruser):

sudo visudo -f /etc/sudoers.d/wakedeck
youruser ALL=(ALL) NOPASSWD: /sbin/shutdown

Trage im Bearbeitungsbildschirm des Geräts den Host (IP oder Name), den SSH-Benutzer (dein Kontoname auf dem PC) und den Port (22) ein. Tippe auf Jetzt herunterfahren. Prüfe beim ersten Mal, ob der angezeigte Fingerabdruck mit dem des PCs übereinstimmt, und tippe dann auf Vertrauen. Der Fingerabdruck des PCs:

Linux

ssh-keygen -lf /etc/ssh/ssh_host_ecdsa_key.pub

Windows

ssh-keygen -lf $env:ProgramData\ssh\ssh_host_ecdsa_key.pub

macOS

ssh-keygen -lf /etc/ssh/ssh_host_ecdsa_key.pub

„Der PC hat den SSH-Schlüssel abgelehnt“: falscher Schlüssel oder Benutzername. „Verbindung nicht möglich“: Der PC ist aus, oder Host, Port oder Firewall stimmen nicht. „Der PC hat mit einem Fehler geantwortet“: Unter Linux oder macOS ist meist die sudoers-Regel schuld. „Der SSH-Schlüssel des PCs hat sich geändert“: Der PC wurde neu installiert oder seine SSH-Schlüssel wurden neu erzeugt; vertraue dem neuen Schlüssel nur, wenn du damit rechnest.

3. Unterwegs (VPN)

Von außerhalb deines Heimnetzes brauchst du zuerst einen Weg hinein, zum Beispiel ein WireGuard- oder Tailscale-VPN. Ein Magic Packet ist ein Broadcast, und viele VPNs leiten keine Broadcasts weiter. Trage die Broadcast-Adresse deines Netzwerks (zum Beispiel 192.168.1.255) im Gerät ein. Klappt das Aufwecken aus der Ferne trotzdem nicht, ist die übliche Lösung ein kleines, immer eingeschaltetes Gerät zu Hause, das das Paket für dich sendet (ein Router mit Wake-on-LAN oder ein Raspberry Pi). Das Herunterfahren per SSH funktioniert über ein VPN, solange die Adresse des PCs erreichbar ist.

Probleme aus der Ferne: „keine Netzwerk- oder VPN-Verbindung“ bedeutet, dass das Telefon keine Route zu dieser Adresse hat; verbinde zuerst das VPN. „Broadcast-Adresse nicht gefunden“ bedeutet, dass der Name oder die Adresse im Gerät nicht aufgelöst werden kann. Ein VPN kann das Paket auch annehmen und nie zustellen: Die App kann das nicht erkennen, weil ein Magic Packet keine Antwort hat. Prüfe, ob der PC angeht, und sieh dir seinen Status in der Liste an.
